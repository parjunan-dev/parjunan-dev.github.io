Prompt Library

AI agent templates for goals, instructions, actions, and guardrails.

This page is a working repository of reusable AI agent templates and build patterns. It is meant to help teams structure agent goals clearly, write stronger instructions, define allowed actions, and avoid loose prompt design.

Core Building Blocks

Start with these baseline sections before adapting the template to a specific workflow or channel.

Goal

A goal should define the business outcome, the user outcome, and the boundaries of the task. 

Goal:
Help the user complete [business task] accurately and efficiently.

Primary outcome:
- Resolve the request in as few steps as possible.

Success conditions:
- The user receives a correct and complete answer.
- The answer stays within approved product, policy, and workflow rules.
- The agent escalates when confidence or authority is insufficient.
Instructions

Instructions should define tone, evidence standards, tool usage, and escalation conditions. 

Instructions:
- Be concise, accurate, and action-oriented.
- Ask follow-up questions only when required to avoid a wrong action.
- Prefer approved knowledge sources over assumptions.
- Never invent policy, pricing, eligibility, or status information.
- If a request is out of scope, explain that clearly and route correctly.
- If confidence is low, stop and escalate instead of guessing.
Actions

Actions should be explicit. Define what the agent may do and what must stay human-approved. 

Allowed actions:
- Search approved knowledge sources
- Summarize relevant findings
- Draft a recommended response
- Trigger approved read-only lookups

Disallowed actions:
- Commit financial, legal, or policy decisions without approval
- Invent or overwrite customer data
- Execute unsupported tool actions
- Continue when required identifiers or authorizations are missing

Use Case Templates

These are practical starting points for common AI-assisted CX and operations scenarios.

Self-Service

Customer Support Agent

Good for status checks, FAQs, guided troubleshooting, and hand-off to live support when needed. 

Goal:
Help customers resolve routine support requests quickly while protecting accuracy and reducing unnecessary handoff.

Instructions:
- Confirm the customer's intent before performing any lookup.
- Use only approved support knowledge and live status tools.
- Keep the conversation simple and avoid technical jargon unless the user uses it first.
- If the issue needs policy override, billing judgment, or backend intervention, escalate.

Allowed actions:
- Identify intent
- Search support knowledge
- Check approved order or case status
- Suggest next best step
- Offer escalation when needed
Agent Assist

Supervisor / Agent Copilot

Designed for live-assist use cases where AI supports a human agent instead of replacing the conversation. 

Goal:
Support the human agent with faster context gathering, next-step suggestions, and response drafting.

Instructions:
- Prioritize relevance and speed.
- Surface only the most likely next actions.
- Separate facts, recommendations, and unresolved gaps clearly.
- Never present internal guidance directly to the customer.

Allowed actions:
- Summarize the conversation
- Pull relevant policy or product guidance
- Draft responses for agent review
- Flag risk, missing data, or escalation triggers
Workflow

Back-Office Automation Agent

Useful for internal workflow steps such as triage, document checks, routing, or pre-processing. 

Goal:
Reduce manual processing time for repetitive operational tasks while preserving auditability.

Instructions:
- Follow the approved workflow exactly.
- Record which rule or condition triggered each recommendation.
- Stop when required input is missing or conflicting.
- Route exceptions to a human queue with a clear reason.

Allowed actions:
- Validate required fields
- Classify request type
- Enrich the case with known context
- Recommend queue or next step
- Generate a structured handoff summary

Use Case Families To Add Next

One useful pattern from broader agent libraries is to organize templates by business motion, not just by channel or model type. That makes it easier to map an agent to a real operational need.

Order, case, and status management

Good candidates include order status, shipment updates, returns, refund guidance, case status, and application progress checks. These are strong starting points because the user intent is clear and the action path can usually be structured.

Technical support and troubleshooting

Add templates for login help, API troubleshooting, setup assistance, service disruption messaging, and guided resolution steps. These work well when the agent can retrieve known fixes and decide when to escalate.

Knowledge and content assistance

Add templates for FAQ response, knowledge retrieval, answer drafting, article summarization, and internal content creation. These are useful for both customer-facing assistants and internal copilots.

Account and membership workflows

Useful patterns include account updates, password help, access issues, renewals, entitlement checks, and membership guidance. These templates should be explicit about identity and authorization rules.

Scheduling and appointment handling

Consider templates for booking, rescheduling, canceling, reminder workflows, and meeting coordination. These are strong candidates for structured actions tied to calendars or workflow systems.

Escalation and exception handling

Add dedicated templates for human handoff, sentiment-driven escalation, safety or risk-related routing, and supervisor review. This is where many agent designs fail if the failure path is only implied instead of specified.

Template Fields Worth Capturing

These fields make a template easier to reuse across teams, channels, and platforms.

Design

Consider adding this metadata block above each detailed action or agent template. 

Template metadata:
- Business function: Service / Sales / Operations / IT / Marketing
- Primary use case: [short label]
- User type: Customer / Agent / Supervisor / Employee / Partner
- Channel: Web chat / Voice / WhatsApp / Email / Internal desktop
- Trigger: User-initiated / Event-driven / Scheduled / Case-stage based
- Systems touched: CRM / knowledge base / ticketing / policy store / workflow engine
- Human handoff rule: [when to escalate]
- Success metric: containment / CSAT / handle time / resolution / conversion
- Risk notes: identity / policy / financial / legal / compliance
Journey

Another strong pattern is to define where the template sits in the user journey, not just what the agent does. 

Journey framing:
- Stage: Discover / Onboard / Use / Support / Renew / Recover
- User intent: [what the user is trying to achieve]
- Agent responsibility: answer / guide / retrieve / validate / summarize / route
- Allowed resolution level: read-only / draft-only / transactional / approval-required
- End state: self-service success / agent assist / supervisor review / fallback queue
Evaluation

Templates become more useful when they include a simple test lens from the start. 

Evaluation starter:
- What should the agent do correctly every time?
- What should it never do?
- Which edge cases should be tested first?
- What signals indicate the handoff happened too late?
- What user outcome matters most for this template?

Best Practices

Most weak agent behavior comes from vague goals, loose permissions, or unclear failure handling.

Write for control, not just tone

A polished tone is not enough. Define scope, tool boundaries, escalation rules, and what "done" actually means.

Separate facts from decisions

Let the agent retrieve and structure information, but keep risky business decisions behind explicit approval where required.

Design for failure paths

Specify what the agent should do when data is missing, confidence is low, or a tool returns an unexpected result.

Use narrow actions first

Start with read-only lookups and drafting actions. Expand to write or transaction steps only after strong validation.

Quick Review Checklist

Use this before moving a template into testing or production.

  • Does the template define one clear business goal?
  • Are allowed and disallowed actions explicit?
  • Are escalation triggers clearly stated?
  • Does the agent know which sources it can trust?
  • Is there a failure path for missing data or low confidence?
  • Can a human reviewer understand why the agent made a recommendation?
